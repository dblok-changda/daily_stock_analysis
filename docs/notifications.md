# Notification Guide

This guide documents notification channels, GitHub Actions environment mapping,
routing, noise control, and rollback boundaries.

## Channel Matrix

| Channel | Minimal configuration | Optional configuration | Notes |
| --- | --- | --- | --- |
| WeChat Work | `WECHAT_WEBHOOK_URL` | `WECHAT_MSG_TYPE` | Webhook channel. |
| Feishu Webhook | `FEISHU_WEBHOOK_URL` | `FEISHU_WEBHOOK_SECRET`, `FEISHU_WEBHOOK_KEYWORD` | Webhook URL is preferred for simple group delivery. |

| Slack | `SLACK_WEBHOOK_URL` or `SLACK_BOT_TOKEN` + `SLACK_CHANNEL_ID` | - | Bot mode is preferred when images must be uploaded to the same channel. |

## Static Availability Rules

Minimal channel keys enable a channel. Advanced keys tune behavior but do not
enable a channel by themselves.

`NOTIFICATION_*_CHANNELS` route already-enabled channels only. Empty route values
mean all configured channels for that route.

The default workflow still does not map `MARKDOWN_TO_IMAGE_CHANNELS` or
`MERGE_EMAIL_NOTIFICATION`. They are behavior switches rather than channel
credentials; mapping them automatically would change runtime behavior for users
who only intended to store configuration.

## ntfy

`NTFY_URL` is a full topic endpoint:

```bash
NTFY_URL=https://ntfy.sh/my-topic
NTFY_TOKEN=
```

Self-hosted examples:

```bash
NTFY_URL=https://ntfy.example.internal/team-alerts
NTFY_TOKEN=optional-bearer-token
```

## Gotify

`GOTIFY_URL` is the Gotify server base URL, not the `/message` endpoint:

```bash
GOTIFY_URL=https://gotify.example
GOTIFY_TOKEN=app-token
```

Reverse proxy path prefixes are allowed:

```bash
GOTIFY_URL=https://example.com/gotify
GOTIFY_TOKEN=app-token
```

The sender appends `/message` and sends the application token in the
`X-Gotify-Key` header.

## Routing

| Route type | Environment key | Typical producers |
| --- | --- | --- |
| `report` | `NOTIFICATION_REPORT_CHANNELS` | Single-stock reports, aggregate daily reports, market review reports, merged reports, Feishu document success links |
| `alert` | `NOTIFICATION_ALERT_CHANNELS` | EventMonitor and Alert Center triggers |
| `system_error` | `NOTIFICATION_SYSTEM_ERROR_CHANNELS` | Reserved; no automatic system-error producer is added |

Interactive commands with source context, such as DingTalk, Feishu, and Telegram
sessions, skip static notification channels. Scheduled runs, CLI runs, API tasks,
and tasks without source context still use report routing.

`MERGE_EMAIL_NOTIFICATION` does not need route-specific configuration. If `email`
remains in the report route, the existing merged-email behavior is preserved.

## Noise Control

| Key | Default | Behavior |
| --- | --- | --- |
| `NOTIFICATION_DEDUP_TTL_SECONDS` | `0` | Suppress the same stable dedup key within the TTL; `0` disables dedup. |
| `NOTIFICATION_COOLDOWN_SECONDS` | `0` | Rate-limit the same cooldown key within the window; `0` disables cooldown. |
| `NOTIFICATION_QUIET_HOURS` | empty | Quiet-hours window in `HH:MM-HH:MM` format, including overnight ranges. |
| `NOTIFICATION_TIMEZONE` | empty | IANA timezone for quiet hours; empty follows the runtime local timezone. |
| `NOTIFICATION_MIN_SEVERITY` | empty | Allowed values: `info`, `warning`, `error`, `critical`; empty disables severity filtering. |
| `NOTIFICATION_DAILY_DIGEST_ENABLED` | `false` | Reserved flag; the current implementation does not send or persist daily digests. |

For Actions and Docker, set `NOTIFICATION_TIMEZONE` explicitly to avoid host
timezone ambiguity.

## Failure Boundaries

Report notification dispatch sends to each static channel independently after
route filtering. A failed channel is logged and recorded as failed, but it does
not skip later channels and does not interrupt the analysis main flow.

Alert notification attempts are recorded separately by the Alert Center when a
real trigger is sent.

## Security

Use Secrets for tokens, passwords, webhook URLs, private gateway URLs, and
headers containing authentication or tenant data. Variables are suitable for
non-sensitive behavior options such as message type, sender display name,
routing, quiet hours, and timezone.

`WEBHOOK_VERIFY_SSL=false` is acceptable only for trusted internal self-signed
webhooks. Do not disable certificate verification on public routes.

## Rollback

Older versions ignore newer `NTFY_*`, `GOTIFY_*`, routing, and noise-control
keys. To avoid misleading configuration after rollback, remove those keys from
`.env` or Actions settings as part of the rollback.
